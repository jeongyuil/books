## Section 1.1: 개요

SQL (Structured Query Language)는 관계형 데이터베이스 관리 시스템 (RDBMS)에 저장된 데이터를 관리하기 위해 설계된 특수 목적의 프로그래밍 언어이다. SQL과 유사한 언어는 관계형 데이터 스트림 관리 시스템 (RDSMS) 또는 NoSQL 데이터베이스에서도 사용될 수 있다.

SQL은 3개의 주요 하위 언어로 구성되어 있다.

1. DDL (Data Definition Language): 데이터베이스 구조를 만들거나 수정한다.
2. DML (Data Manipulation Language): 데이터의 읽기, 삽입, 업데이트 또는 삭제 기능을 수행한다.
3. DCL (Data Control Language): 데이터베이스에 저장된 데이터의 접근을 제어한다.

[Wikipedia 의 SQL 관련 문서](https://en.wikipedia.org/wiki/SQL)

DML의 주요 작업은 INSERT, SELECT, UPDATE 및 DELETE 입니다. 이 외에 3가지 쓰기 작업 (INSERT, SELECT, DELETE)을 모두 수행할 수 있는 MERGE 가 최근에 추가되었다.

[Wikipedia의 CRUD 관련 문서](https://app.notion.com/p/21a843e9e96e47bb893dd1384fb58b8e?pvs=21)

많은 SQL 데이터베이스는 클라이언트/ 서버 시스템으로 구현된다. 마이크로소프트가 개발한 ‘SQL 서버’는 이런 SQL 데이터베이스 중 하나이다. SQL 서버는 SQL 언어를 사용하지만, 데이터베이스와 관련된 일부 정보는 SQL 서버 문서를 통해 확인하길 바란다.

# Chapter 2: 식별자 (Identifier)

이 챕터에서는 식별자 (Identifier) 즉, 테이블, 열 및 기타 데이터베이스 객체 등의 이름을 지을 때 구문 규칙에 대해서 설명한다. SQL의 종류에 따라 사용되는 식별자와 특징이 다르다. 자세한 내용은 링크되어있는 참고 자료를 확인하면 좋겠다.

## Section 2.1: 따옴표로 묶이지 않은 식별자 (Unquoted identifiers)

따옴표 (’)로 묶이지 않은 식별자는 문자 (a-z), 숫자 (0-9) 그리고 밑줄 (_)을 사용할 수 있으며 문자로 시작해야 한다.

SQL 구현 및 데이터베이스 설정에 따라 다른 문자가 허용될 수 있으며, 일부는 첫 번째 문자로도 허용된다.

- MS SQL: @, $, #, 기타 유니코드 문자 ([참고 자료](https://learn.microsoft.com/en-us/sql/relational-databases/databases/database-identifiers?view=sql-server-ver16))
- MySQL: $ ([참고 자료](https://dev.mysql.com/doc/refman/5.7/en/identifiers.html))
- Oracle: $, #, 데이터베이스 문자 집합의 기타 문자 ([참고 자료](https://docs.oracle.com/database/121/SQLRF/sql_elements008.htm#SQLRF00223))
- PostgreSQL: $, 기타 유니코드 문자 ([참고 자료](https://www.postgresql.org/docs/current/sql-syntax-lexical.html))

따옴표로 묶이지 않은 식별자는 대소문자를 구분하지 않는다. 이 작업을 처리하는 방법은 SQL 구현 방법에 따라 달라진다.

- MS SQL: 대소문자를 보존한다. 데이터베이스 문자 설정에 의해 정의되며, 대소문자를 구분할 수 있다.
- MY SQL: 대소문자를 보존한다. 데이터베이스 설정과 기본 파일 시스템에 따라 대소문자를 구분할 수 있다.
- Oracle: 대문자로 변환한다. 변환 이후 따옴표로 묶인 식별자처럼 처리된다.
- PostgreSQL: 소문자로 변환한다. 변환 이후 따옴표로 묶인 식별자처럼 처리된다.
- SQLite: 대소문자를 보존한다. 단, ASCII 문자에 대해서만 대소문자를 구분하지 않는다.

# Chapter3: 데이터 타입 (Data Types)

## Section 3.1: DECIMAL 과 NUMERIC

고정된 정밀도 (precision)와 척도 (scale)를 갖는 십진수 숫자를 의미하며, DECIMAL 과 NUMERIC 은 기능적으로 동일하다.

구문:

```sql
DECIMAL (precision [ , scale])
NUMERIC (precision [ , scale])
```

예제:

```sql
SELECT CAST(123 AS DECIMAL(5,2) --결과값 123.00
SELECT CAST(12345.12 AS NUMERIC(10,5) --결과값 12345.12000
```

## Section 3.2: FLOAT 과 REAL

부동 소수점을 표현하는 숫자 데이터로, 근사값을 나타내는 데이터 유형이다.

```sql
SELECT CAST( PI() AS FLOAT) --결과값 3.14159265358979
SELECT CAST( PI() AS REAL) --결과값 3.141593
```

## Section 3.3: Integers

정수를 표현하는 숫자 데이터로, 정확한 값을 나타내는 데이터 유형이다.

| Data Type | Range | Storage |
| --- | --- | --- |
| bigint | 2^63 (-9,223,372,036,854,775,808)
~ 2^63-1 (9,223,372,036,854,775,807) | 8 Bytes |
| int | 2^31 (-2,147,483,648)
~ 2^31-1 (2,147,483,647) | 4 Bytes |
| smallint | 2^15 (-32,768)
~ 2^15-1 (32,767) | 2 Bytes |
| tinyint | 0 ~ 255 | 1 Byte |

## Section 3.4: MONEY 와 SMALLMONEY

통화 또는 통화의 가치를 나타내는 데이터 유형이다.

| Data type | Range | Storage |
| --- | --- | --- |
| money | 922,337,203,685,477.5808 
~ 922,337,203,685,477.5807 | 8 Bytes |
| smallmoney | 214,748.3648

## Section 3.5: BINARY 와 VARBINARY

고정 길이 또는 가변 길이를 나타내는 이진법 데이터 유형이다.

구문:

```sql
BINARY [ ( n_bytes ) ]
VARBINARY [ ( n_bytes | max ) ]
```

```sql
SELECT CAST(12345 AS BINARY(10)) -- 0x00000000000000003039
SELECT CAST(12345 AS VARBINARY(10)) -- 0x00003039
```

## Section 3.6: CHAR 와 VARCHAR

고정 길이 또는 가변 길이를 나타내는 문자열 데이터 유형이다.

구문:

```sql
CHAR [ ( n_chars ) ]
VARCHAR [ ( n_chars ) ]
```

예제:

```sql
SELECT CAST('ABC' AS CHAR(10)) -- 'ABC ' (오른쪽에 공백으로 채워짐)
SELECT CAST('ABC' AS VARCHAR(10)) -- 'ABC' (가변 문자이기 때문에 공백 없음)
SELECT CAST('ABCDEFGHIJKLMNOPQRSTUVWXYZ' AS CHAR(10)) -- 'ABCDEFGHIJ' (10개 문자로 잘림)
```

## Section 3.7: NCHAR 와 NVARCHAR

고정 길이 또는 가변 길이의 유니코드 (UNICODE) 문자열 데이터 유형

구문:

```sql
NCHAR [ ( n_chars ) ]
NVARCHAR [ ( n_chars | MAX ) ]
```

## Section 3.8: UNIQUEIDENTIFIER

16 바이트 GUID / UUID

```sql
DECLARE @GUID UNIQUEIDENTIFIER = NEWID();
SELECT @GUID -- 'E28B3BD9-9174-41A9-8508-899A78A33540'
DECLARE @bad_GUID_string VARCHAR(100) = 'E28B3BD9-9174-41A9-8508-899A78A33540_foobarbaz'
SELECT
 @bad_GUID_string, -- 'E28B3BD9-9174-41A9-8508-899A78A33540_foobarbaz'
 CONVERT(UNIQUEIDENTIFIER, @bad_GUID_string) -- 'E28B3BD9-9174-41A9-8508-899A78A33540
```

# Chapter 4: NULL

SQL 뿐만 아니라 일반적인 프로그래밍에서 `NULL`은 문자 그대로 “아무 것도 없음”을 의미한다. SQL에서는 “어떤 값도 없다.”라는 표현이 더 이해하기 쉽다.

빈 문자열 `''` 또는 숫자 `0`과 같이 실제로는 `NULL`이 아니지만, `NULL`처럼 보이는 값들과 잘 구분할 필요가 있다.

또한, ‘NULL’ 과 같이 따옴표로 `NULL` 을 묶지 않도록 주의해야 한다. ‘NULL’이라고 쓰면 이것은 텍스트로 인식이 되어 `NULL` 이 아니게 입력된다. 이로 인해 오류가 발생하거나 잘못된 데이터 설정이 될 수 있다.

## Section 4.1: 쿼리에서 NULL 필터링

NULL을 필터링하는 방법은 일반 적인 값(value)의 필터링과 조금 다르다.

```sql
SELECT * FROM Employees WHERE ManagerId IS NULL ;
SELECT * FROM Employees WHERE ManagerId IS NOT NULL ;
```

여기서 주의해야할 점은, NULL은 무엇과도 동일하지 않기 때문에 등호 연산자를 사용해서 필터링 하면 안된다. 예를들어, = NULL 라던가 != NULL 또는 <> NULL 과 같은 표현을 쓰면 WHERE 구문에서 오류가 발생하게 된다.

WHERE 는 조건이 FALSE 또는 UNKNOWN 인 모든 열은 표시하지 않고, 조건이 TRUE 인 경우 열만 표시한다.

## Section 4.2: 테이블에서 Nullable 열(columns) 설정

테이블을 생성할 때 열을 nullable 또는 non-nullable 로 설정 할 수 있다.

```sql
CREATE TABLE MyTable
(
 MyCol1 INT NOT NULL, -- non-nullable
 MyCol2 INT NULL -- nullable
) ;
```

제약 조건을 NOT NULL 으로 명시하지 않는다면, 기본 설정값으로 모든 열은 nullable 으로 설정된다

만약 non-nullable 으로 설정된 열에 NULL 을 할당하려고 하면 오류가 발생한다.

```sql
INSERT INTO MyTable (MyCol1, MyCol2) VALUES (1, NULL) ; -- 잘 작동한다
INSERT INTO MyTable (MyCol1, MyCol2) VALUES (NULL, 2) ;
 -- cannot insert
 -- the value NULL into column 'MyCol1', table 'MyTable';
 -- column does not allow nulls. INSERT fails.
 -- MyCol1 이 NOT NULL 이므로, 이런 에러 메시지를 보게 된다.
```

## Section 4.3: 필드에서 NULL 업데이트(Update)

아래와 같은 방법으로 필드를 NULL 으로 설정할 수 있다.

```sql
UPDATE Employees
SET ManagerId = NULL
WHERE Id = 4
```

## Section 4.4: 필드에서 NULL 삽입(Insert)

만약 전화번호와 매니저가 확인되지 않는 직원을 직원 관리 테이블에 등록하는 경우, 아래와 같이 insert 구문을 사용해 작성할 수 있다.

```sql
INSERT INTO Employees
 (Id, FName, LName, PhoneNumber, ManagerId, DepartmentId, Salary, HireDate)
VALUES
 (5, 'Jane', 'Doe', NULL, NULL, 2, 800, '2016-07-22') ;
```

# Chapter 6: SELECT 구문

SELECT 구문은 SQL 쿼리의 핵심이다. 쿼리 실행으로 인한 결과를 정의하며, 데이터베이스의 어떤 항목을 쿼리해야 하는지 정의하는 FROM 절과 대부분 함께 쓰인다.

## Section 6.1: 와일드카드 문자(wildcard character)를 사용하여 쿼리의 모든 열 선택

아래의 두 예시 테이블을 확인해보자.

**테이블 명: Employees**

| Id | FName | LName | DepId |
| --- | --- | --- | --- |
| 1 | James | Smith | 3 |
| 2 | John | Johnson | 4 |

**테이블 명: Departments**

| Id | Name |
| --- | --- |
| 1 | Sales |
| 2 | Marketing |
| 3 | Finance |
| 4 | IT |

**간단한 SELECT 구문**

* 은 테이블에서 사용 가능한 모든 열을 선택하는 데 사용되는 와일드카드 문자(wildcard character)이다.

열 이름을 구체적으로 명시하지 않고 * 문자를 사용하면, FROM 조건 내의 모든 테이블의 모든 열을 반환한다. 이는 JOIN 을 사용 시, 접근하는 모든 테이블에 적용된다.

아래의 쿼리를 적용해보자.

```sql
SELECT * FROM Employees;
```

위의 쿼리는 아래와 같이 Employees 테이블의 모든 열의 모든 필드를 반환한다.

| Id | FName | LName | DepId |
| --- | --- | --- | --- |
| 1 | James | Smith | 3 |
| 2 | John | Johnson | 4 |

**점 표기법**

특정 테이블에서 모든 값을 SELECT 하기위해 와일드카드 문자를 점(.) 표기법으로 테이블에 적용할 수 있다.

아래의 쿼리를 적용해보자.

```sql
SELECT
    Employees.*,
    Departments.Name
FROM
Employees
JOIN
Departments
ON Departments.Id = Employees.DeptId;
```

위 쿼리를 실행하면 Employees 테이블의 모든 필드와 Departments 테이블의 이름 필드 만을 합쳐서 반환한다.

| Id | FName | LName | DepId |
| --- | --- | --- | --- |
| 1 | James | Smith | 3 |
| 2 | John | Johnson | 4 |

**주의사항**

일반적으로 프로덕션 코드 등의 실무에서는 * 를 사용하지 않는 것을 추천한다. 다음과 같은 여러 잠재적인 문제를 발생시킬 수 있기 때문이다.

1. 불필요한 데이터를 데이터베이스 엔진이 읽어 프론트엔드 코드로 전송하기 때문에 과도한 IO 로드, 네트워크 부하, 메모리 사용 등이 발생한다. 이는 길고 복잡한 노트나 첨부 파일과 같은 대용량의 필드가 있는 경우 특히 문제가 될 수 있다.
2. 데이터베이스가 SELECT <columns> FROM <table> 구분 보다 더 복잡한 쿼리를 처리할 때 내부 결과를 디스크에 스풀 처리 해야하는 경우가 발생할 수 있다. 이 때 추가적인 IO 로드가 발생할 수 있다.
3. 불필요한 열의 일부가 아래와 같은 경우 추가적인 프로세싱 또는 더 많은 IO 가 발생할 수 있다.
    1. 데이터베이스 내에서 계산된 열인 경우
    2. 뷰(view)에서 SELECT 시, 쿼리 최적화 프로그램에서 최적화할 수 있는 테이블이나 뷰의 열인 경우
4. 향후 테이블과 뷰에 열이 추가되어 열의 의미가 모호해질 경우 예상치 못한 오류가 발생할 수 있다.

```sql
SELECT * FROM orders JOIN people ON people.id = orders.personid ORDER
BY displayname;
```

예를 들어 위의 구문처럼 관리자가 작업에 참조할 수 있도록 displayname 이라는 열을 orders 테이블에 추가했다면, 출력에 동일한 열 이름이 두번 나타나기 때문에 ORDER BY 절의 명령이 모호해져 오류가 발생할 수 있다. 최신 MS SQL 에서는 “ambiguous column name” 즉, 모호한 열 이름 이라는 오류 메시지를 출력해준다. 만약 이 예제에서 다루지 않는 경우, 새로 추가된 열이 반환된 이름 중 첫 번째 열이기 때문에 응용 프로그램 코드는 의도된 사람 이름과 대응하는 주문 이름을 보여줄 것이다.

**이런 위험에도 불구하고, *를 사용할 수 있는 경우**

프로덕션 코드에서는 * 사용을 피하는 것이 좋지만, 조사나 프로토타입 작업을 위해 데이터베이스에 수동 쿼리를 수행할 때는 사용해도 된다.

응용 프로그램의 디자인 결정으로 인해 불가피하게 * 를 사용해야하는 경우가 발생한다. 이런 상황에서는 가능한 경우 * 보다는 tablealias.* 를 사용하길 추천한다.

```sql
SELECT A.col1, A.Col2 FROM A WHERE EXISTS (SELECT * FROM B where A.ID = B.A_ID);
```

위 구문과 같이 EXISTS 사용하는 경우, B에서 데이터를 반환하지 않는다. 따라서 JOIN이 필요하지 않으며 엔진은 B의 값이 반환되지 않는다는 것을 알고 있으므로 *를 사용해도 성능이 저하되지 않는다. 마찬가지로 COUNT(*) 역시 실제로 열을 반환하지 않으므로 사용해도 괜찮다. 따라서 필터링 목적으로 사용되는 열만 읽고 처리하는데 사용은 용인된다.

## Section 6.2: 열의 별칭을 사용해 SELECT 하기

열 별칭(Column aliases)은 주로 코드를 줄이고 열의 이름을 더 읽기 쉽게 만들기 위해 사용된다. 

긴 테이블의 이름과 불필요한 열의 식별을 피할 수 있으므로 코드가 짧아진다. 예를 들어, 테이블에 2개의 ID가 있을 수 있지만 명령문에는 하나만 사용하는 방식이다. 테이블 별칭과 함께 이를 통해 데이터베이스 구조에서 더 긴 설명 이름을 사용하면서 해당 구조에 대한 쿼리를 간결하게 유지할 수 있다.

또만, 뷰에서 계산된 출력의 이름을 지정하기 위해 사용하기도 한다.

별칭은 큰따옴표 (”)를 사용하여 모든 버전의 SQL에서 만들 수 있다.

```sql
SELECT
    FName AS "First Name",
    MName AS "Middle Name",
    LName AS "Last Name"
FROM Employees;
```

**다양한 버전의 SQL**

Microsoft SQL Server 에서는 작은따옴표 (’), 큰따옴표 (”), 대괄호 ([ ]) 를 이용하여 별칭을 만드는 것이 가능하다.

```sql
SELECT
    FName AS "First Name",
    MName AS 'Middle Name',
    LName AS [Last Name]
FROM Employees;
```

| **SELECT** | **FROM** | **WHERE** |
| --- | --- | --- |
| James | John | Smith |
| John | James | Johnson |
| Michael | Marcus | Williams |

또한, 아래와 같이 열 별칭은 ORDER BY 와 같은 동일한 쿼리의 마지막 절에 사용할 수 있다.

```sql
SELECT
    FName AS FirstName,
    LName AS LastName
FROM Employees
ORDER BY
    LastName DESC;
```

하지만, 아래와 같이는 사용할 수 없다.

```sql
SELECT
    FName AS SELECT,
    LName AS FROM
FROM
Employees
ORDER BY
    FROM DESC
```

(SELECT 와 FROM) 과 같은 예약어를 별칭으로 사용하는 실수로 인해 수많은 오류가 발생할 수 있다.

## Section 6.3: 특정 개별의 열을 SELECT 하기

```sql
SELECT
    PhoneNumber,
    Email,
    PreferredContact
FROM Customers;
```

위 쿼리 구문은 Customers 테이블의 모든 열에서 PhoneNumber, Email, PreferredContact 열을 불러온다. 또한 반환된 열들은 SELECT 절의 각 열 순서를 갖는다. 

**쿼리 결과:**

| **PhoneNumber** | **Email** | **PreferredContact** |
| --- | --- | --- |
| 3347927472 | william.jones@example.com | PHONE |
| 2137921892 | dmiller@example.net | EMAIL |
| NULL | richared0123@example.com | EMAIL |

만약 여러 테이블을 조인하는 경우, [테이블 이름].[열 이름] 과 같은 형식과 같이 특정 각 열의 바로 앞에 테이블의 이름을 지정하여 원하는 테이블을 지정할 수 있다.

```sql
SELECT
    Customers.PhoneNumber,
    Customers.Email,
    Customers.PreferredContact,
    Orders.Id AS OrderId
FROM
Customers
LEFT JOIN
    Orders ON Orders.CustomerId = Customers.Id
```

- Note: 위 쿼리 구문에서 AS OrderId 는 Orders 테이블의 Id 필드가 OrderId 열으로 반환됨을 의미한다. 자세한 내용은 ‘Section 6.2: 열 별칭을 이용해 SELECT 하기’를 참고한다.

너무 긴 테이블 이름을 피하기 위해 테이블 별칭을 사용할 수 있다. 테이블 별칭을 사용하면, 조인 절의 각 필드에  긴 테이블 이름을 작성하지 않아도 된다. 

자체 조인(Self Join, 동일한 테이블의 두 인스턴스 간의 조인)을 수행하는 경우 테이블 별칭을 사용하여 테이블을 구별해야 한다.

예를 들어, Customers c 또는 Customers AS c 와 같은 형식으로 테이블 별칭을 작성할 수 있다. 여기에서 c는 고객의 별칭으로 작동하며 [c.Email](http://c.Email) 과 같은 형식으로 이메일을 선택할 수 있습니다. 사례 확인을 통해 아래 예시 코드를 참고한다.

```sql
SELECT
    c.PhoneNumber,
    c.Email,
    c.PreferredContact,
    o.Id AS OrderId
FROM
Customers c
LEFT JOIN
    Orders o ON o.CustomerId = c.Id;
```

## Section 6.4: 특정 숫자의 기록을 SELECT 하기

[SQL 2008 표준](https://en.wikipedia.org/wiki/SQL:2008)에서 정의한 것과 같이 FETCH FIRST 절을 통해 반환되는 레코드의 수를 제한할 수 있다.

```sql
SELECT Id, ProductName, UnitPrice, Package
FROM Product
ORDER BY UnitPrice DESC
FETCH FIRST 10 ROWS ONLY;
```

이 표준은 일부 관계형 데이터베이스 시스템 (RDMS)의 최신 버전에서만 지원된다. 다른 시스템에서는 공급업체별 비 표준 구문이 제공된다. Progress OpenEdge 에서는 11.x 버전부터 FETCH FIRST <n> ROWS ONLY 구문을 지원한다.

또한, FETCH FIRST <n> ROWS ONLY 절 앞에 OFFSET <m> ROWS 를 사용하면 행을 가져오기 전에 행 건너뛰기를 허용한다. 아래의 예시를 참고한다.

```sql
SELECT Id, ProductName, UnitPrice, Package
FROM Product
ORDER BY UnitPrice DESC
OFFSET 5 ROWS
FETCH FIRST 10 ROWS ONLY;
```

다음 쿼리는 SQL Server 와 MS Access 에서 지원된다.

```sql
SELECT TOP 10 Id, ProductName, UnitPrice, Package
FROM Product
ORDER BY UnitPrice DESC
```

MySQL 과 PostgreSQL 에서는 FETCH FIRST 와 동일한 명령을 실행하기 위해서 LIMIT 키워드를 사용한다. 아래의 예시를 참고한다.

```sql
SELECT Id, ProductName, UnitPrice, Package
FROM Product
ORDER BY UnitPrice DESC
LIMIT 10;
```

Oracle 에서는 ROWNUM 를 사용해 동일한 결과를 얻을 수 있다.

```sql
SELECT Id, ProductName, UnitPrice, Package
FROM Product
WHERE ROWNUM <= 10
ORDER BY UnitPrice DESC;
```

## Section 6.5: 조건을 걸어 SELECT 하기

WHERE 를 사용하는 SELECT 구문은 아래와 같다.

```sql
SELECT column1, column2, columnN
FROM table_name
WHERE [condition];
```

위 쿼리문의 [condition]에서는 >, <, =, <>, >=, <=, LIKE, NOT, IN, BETWEEN 등과 같은 비교 또는 논리 연산자를 사용하여 지정된 SQL 표현식일 수 있다.

다음 명령문은 status 열이 'READY'인 테이블 'Cars'의 모든 열을 반환한다.

```sql
SELECT * FROM Cars WHERE status = 'READY';
```

더 많은 예시를 확인하려면 ‘Chapter 13. WHERE 및 HAVING’을 참조한다.

## Section 6.6: CASE를 사용해 SELECT 하기

그때 그때 상황에 맞춰 결과에 특정 조건을 적용하고 싶을 때는 CASE 구문을 사용한다.

```sql
SELECT CASE WHEN Col1 < 50 THEN 'under' ELSE 'over' END threshold
FROM TableName;
```

또한 아래와 같이 여러 조건을 하나의 구문에 넣을 수 있다.

```sql
SELECT
    CASE WHEN Col1 < 50 THEN 'under'
         WHEN Col1 > 50 AND Col1 <100 THEN 'between'
         ELSE 'over'
    END threshold
FROM TableName;
```

하나의 CASE 구문 안에 다른 CASE 를 가질 수도 있다.

```sql
SELECT
    CASE WHEN Col1 < 50 THEN 'under'
         ELSE
            CASE WHEN Col1 > 50 AND Col1 <100 THEN Col1
            ELSE 'over' END
END threshold
FROM TableName;
```

## Section 6.7: 예약된 키워드 이름의 열 SELECT 하기

열 이름이 예약된 키워드와 일치하는 경우 표준 SQL 에서는 아래와 같이 열 이름을 큰따옴표로 묶어야 한다.

```sql
SELECT
"ORDER",
    ID
FROM ORDERS;
```

열 이름은 대소문자를 구분한다.

일부 관계형 데이터베이스 관리 시스템(DBMS)은 각자 이름을 인용하는 독점적인 방법을 가지고 있다. 예를 들어 SQL Server는 다음과 같은 방식으로 대괄호를 사용합니다. 아래 코드를 참조한다.

```sql
SELECT
[Order],
    ID
FROM ORDERS;
```

MySQL(및 MariaDB)에서는 기본적으로 백틱(`)을 사용합니다.

```sql
SELECT
    `Order`,
    id
FROM orders;
```

## Section 6.8: 테이블 별칭으로 SELECT 하기

```sql
SELECT e.Fname, e.LName
FROM Employees e;
```

Employess 테이블 이름 바로 뒤에 'e'라는 별칭을 지정했다. 이런 방법을 사용하면, 여러 테이블에 동일한 필드 이름이 있는 경우에도 특정 테이블을 선택해 데이터를 불러올 수 있다.

```sql
SELECT e.Fname, e.LName, m.Fname AS ManagerFirstName
FROM Employees e
    JOIN Managers m ON e.ManagerId = m.Id;
```

별칭을 정의하면 기존 테이블 이름은 사용할 수 없다. 그러므로 아래 코드의 쿼리를 실행하면 에러가 발생한다.

```sql
SELECT e.Fname, Employees.LName, m.Fname AS ManagerFirstName
FROM Employees e
JOIN Managers m ON e.ManagerId = m.Id;
```

이 책에서 편의상 사용한 테이블 별칭의 공식적인 명칭은 ‘범위 변수 (range variables)’ 이다. 범위 변수는 INNER JOIN 으로 인한 중복 열 문제를 해결하기 위해 SQL 언어에 도입되었다.

1992 SQL 표준은 NATURAL JOIN (mySQL, PostgreSQL, Oracle 사용 가능, SQL Server에서 아직 사용 불가능)을 도입함으로써 이러한 초기 설계 결함을 수정하였다. NATURAL JOIN의 결과는 중복이 절대 발생하지 않는다.

위의 예제에서 각 테이블의 이름이 다른 열(Id, ManagerId)에는 JOIN 을 할 수 있지만, 이름이 같은 열(LName, FName)에는 JOIN 해서는 안 되며 그 전에 열 이름을 변경해야 한다는 점은 흥미롭다.

```sql
SELECT Fname, LName, ManagerFirstName
FROM Employees
     NATURAL JOIN
     ( SELECT Id AS ManagerId, Fname AS ManagerFirstName
       FROM Managers ) m;
```

위의 구문 처럼, SQL 오류 발생을 막기위해 파생 테이블에 대해 별칭/범위 변수를 선언해야 하지만 실제 쿼리 구문에 이 별칭이 사용되지는 않는 것을 볼 수 있다.

## Section 6.10: Lock 풀고 테이블을 SELECT 하기

테이블의 대부분이 읽기 또는 읽기 전용으로 사용되는 경우에는, 인덱싱이 성능에 도움을 주지 못하고 모든 비트 수가 계산된다. 이 때, 성능 향상을 위해 LOCK 없이 선택 항목을 사용할 수 있다.

SQL Server

```sql
SELECT * FROM TableName WITH (nolock);
```

MySQL

```sql
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT * FROM TableName;
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

Oracle

```sql
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT * FROM TableName;
```

DB2

```sql
SELECT * FROM TableName WITH UR;
```

위 코드에서 UR은 "커밋되지 않은 읽기"를 의미한다.

기록(record) 수정 작업이 진행 중인 테이블에 사용할 경우 예기치 않은 결과가 발생할 수 있으므로 Lock을 풀고 쿼리 사용 시 각별히 유의한다.

## Section 6.11: Aggregate 함수를 사용해 SELECT 하기

**평균 (Average)**

AVG() 집계 함수는 SELECT로 선택된 값들의 평균을 결과로 반환한다.

```sql
SELECT AVG(Salary) FROM Employees;
```

집계 함수는 또한 where 절과 함께 사용할 수 있다.

```sql
SELECT AVG(Salary) FROM Employees where DepartmentId = 1;
```

집계 함수는 또한 group by 절과 함께 사용할 수 있다.

직원이 여러 부서로 분류되어있는 경우, 각 부서의 평균 급여를 찾으려면 다음 쿼리를 사용할 수 있습니다.

```sql
SELECT AVG(Salary) FROM Employees GROUP BY DepartmentId;
```

**최솟값 (Minimum)**

MIN() 집계 함수는 SELECT로 선택된 값들 중 최솟값을 결과로 반환한다.

```sql
SELECT MIN(Salary) FROM Employees;
```

**최댓값 (Maximum)**

MAX() 집계 함수는 SELECT로 선택된 값들 중 최댓값을 결과로 반환한다.

```sql
SELECT MAX(Salary) FROM Employees;
```

**카운트 (Count)**

COUNT() 집계 함수는 SELECT로 선택된 값의 개수를 결과로 반환한다.

```sql
SELECT Count(*) FROM Employees;
```

또한 특정 조건을 만족하는 행의 수를 얻을 수도 있다.

```sql
SELECT Count(*) FROM Employees where ManagerId IS NOT NULL;
```

특정 열을 지정하여 열의 값 수를 가져올 수도 있다. 이 때 NULL 값은 계산되지 않는다.

```sql
Select Count(ManagerId) from Employees;
```

COUNT를 DISTINCT 키워드와 조합하여 고유값 개수를 결과로 반환할 수 있다.

```sql
Select Count(DISTINCT DepartmentId) from Employees;
```

**합계 (Sum)**

SUM() 집계 한수는 SELECT로 선택된 모든 행에 대한 값의 합계를 결과로 반환한다. 

```sql
SELECT SUM(Salary) FROM Employees;
```

## Section 6.12: 열의 여러 값을 조건으로 SELECT 하기

```sql
SELECT * FROM Cars WHERE status IN ( 'Waiting', 'Working' );
```

위 구문과 아래 구문은 의미적으로 동일하다.

```sql
SELECT * FROM Cars WHERE ( status = 'Waiting' OR status = 'Working' );
```

참고: value IN(<값 목록>)은 분리(논리 OR)의 줄임말이다.

## Section 6.13: 열 그룹의 집계(aggregate) 결과 가져오기

**특정 열의 값을 기준으로 행 개수 세기:**

```sql
SELECT category, COUNT(*) AS item_count
FROM item
GROUP BY category;
```

**부서별 평균 소득 가져오기:**

```sql
SELECT department, AVG(income)
FROM employees
GROUP BY department;
```

SELECT 하는 열은 GROUP BY 절에 지정되는 열 또는 집계 함수와 함께 사용한다는 점을 주의한다.

WHERE 절은 GROUP BY와 함께 사용할 수 있다. 하지만 WHERE 는 그룹화를 수행하기 전에 먼저 레코드를 필터링한다.

```sql
SELECT department, AVG(income)
FROM employees
WHERE department <> 'ACCOUNTING'
GROUP BY department;
```

그룹화가 완료된 후 결과를 필터링하는 경우 HAVING 절을 사용한다.

아래 예시는 평균 소득이 1000보다 큰 부서만 보고 싶을 때 사용할 수 있는 쿼리 구문이다.

```sql
SELECT department, AVG(income)
FROM employees
WHERE department <> 'ACCOUNTING'
GROUP BY department
HAVING avg(income) > 1000;
```

## Section 6.14: 결과를 정렬하여 SELECT 하기

```sql
SELECT * FROM Employees ORDER BY LName;
```

위 구문은 Employees 테이블의 모든 열을 반환한다

| **Id** | **FName** | **LName** | **PhoneNumber** |
| --- | --- | --- | --- |
| 2 | John | Johnson | 2468101214 |
| 1 | James | Smith | 1234567890 |
| 3 | Michael | Williams | 1357911131 |

```sql
SELECT * FROM Employees ORDER BY LName DESC;
```

또는

```sql
SELECT * FROM Employees ORDER BY LName ASC;
```

위의 두 구문은 정렬 방향을 변경한다.

하나의 구문에서 정렬 열을 여러 개 지정할 수도 있다. 아래의 예시를 확인한다.

```sql
SELECT * FROM Employees ORDER BY LName ASC, FName ASC;
```

위 예제에서는 먼저 LName별로 결과를 정렬한 다음 동일한 LName을 가진 기록에 대해 FName별로 정렬한다. 이렇게 하면 전화번호부와 유사한 결과를 얻을 수 있다.

ORDER BY 절에 열 이름을 다시 입력하는 시간을 줄이려면, 열의 번호를 대신 사용할 수 있습니다. 열 번호는 1부터 시작한다.

```sql
SELECT Id, FName, LName, PhoneNumber FROM Employees ORDER BY 3;
```

ORDER BY 절에 CASE 문을 포함할 수도 있다.

```sql
SELECT Id, FName, LName, PhoneNumber 
FROM Employees 
ORDER BY CASE WHEN LName='Jones' THEN 0 ELSE 1
END ASC;
```

## Section 6.17: 여러 테이블에서 열 SELECT 하기

```sql
SELECT * FROM
    table1,
    table2;

SELECT
     table1.column1,
     table1.column2,
     table2.column1
FROM
     table1,
     table2;
```

이는 SQL에서 교차 곱 (cross product)이라고 불리며 집합의 교차 곱과 동일하다.

이러한 문장은 하나의 쿼리로 테이블에서 선택한 열들을 반환한다.

각 테이블에서 반환되는 열 사이에는 특별한 관계가 없다.

# Chapter 45: Window 함수

## Section 45.1: 다른 행에 공통 속성이 있는 경우 플래그(flag) 설정하기

| id | name | tag |
| --- | --- | --- |
| 1 | example | unique_tag |
| 2 | foo | simple |
| 42 | bar | simple |
| 3 | baz | hello |
| 51 | quux | world |

```sql
SELECT id, name, tag, COUNT(*) OVER (PARTITION BY tag) > 1 AS flag FROM items;
```

| id | name | tag | flag |
| --- | --- | --- | --- |
| 1 | example | unique_tag | false |
| 2 | foo | simple | true |
| 42 | bar | simple | true |
| 3 | baz | hello | false |
| 51 | quux | world | false |

```sql
SELECT id, name, tag, (SELECT COUNT(tag) 
FROM items B WHERE tag = A.tag) > 1 AS flag FROM items A;
```
